## Scope

`v0.6.27` is a safety-correction release. It differs from its recent
predecessors in a way a reviewer must not miss.

**Protected runtime safety boundaries changed in this release.** Recent releases
have been able to state that none did. This one cannot, and the claim is not
made: `src/atlas_agent/safety/`, `src/atlas_agent/brokers/`,
`src/atlas_agent/execution/`, `src/atlas_agent/risk/` and
`src/atlas_agent/config/` all changed, because that is where the defects were.

Every change is in the refusing direction. None widens what the system may do:

| Area | Change | Direction |
|---|---|---|
| `safety/kill_switch.py` | The advanced switch also consults the `memory/` companion state | Refuses more |
| `brokers/resolver.py` | `can_submit` reads both kill switches, OR never AND | Refuses more |
| `risk/manager.py`, `risk/limits.py` | Three declared limits are now enforced | Rejects more orders |
| `execution/submit_execution.py` | Every gate failure is recorded to the audit log | Records more |
| `config/store.py`, `config/migrate.py` | A write the schema cannot load back is refused | Refuses more |
| `research/_claim_vocabulary.py` | One vocabulary across nine artifact scanners | Refuses more claims |

Three candidates are included: **CAND-033** (risk limits wired), **CAND-035**
(research handler preamble absorbed) and **CAND-037** (per-artifact helper
copies, partial). CAND-032, CAND-034 and CAND-036 remain proposed.

## Included Security Hardening

- The two parallel kill-switch subsystems are documented, and the four consumers
  that read only one of them now read both. `atlas kill` no longer leaves the
  live submit path open — the one genuine fail-open of the audit.
- The kill switch arms even when a broker cannot be built. Arming an emergency
  stop no longer depends on reaching a broker.
- Live-submit opt-in is refused while either kill switch is armed.
- Three declared risk limits — daily loss, leverage, trades per day — are
  enforced rather than declared. The third was printed to the operator by
  `atlas risk check` while having no field behind it.
- A config write the schema cannot load back is refused at three paths that
  could previously make one.
- Constant-time comparison for secrets in the safety and execution paths.
- The anti-fabrication vocabulary is unified across nine artifact scanners.

## Included Provider Evidence Tooling

- Provider and broker evidence remains local, read-only, and non-authorizing.
- No provider or broker execution was enabled by this release.
- The provider artifact modules changed structurally: 76 byte-identical helper
  copies were collapsed to one definition each, and the anti-fabrication claim
  vocabulary was unified across nine artifact scanners. Both were verified against
  the full research suite; the CLI envelopes for all 175 `atlas research`
  subcommands are unchanged.
- The unified claim vocabulary refuses strictly more than any of the nine lists it
  replaced. No artifact that validated before and should have is refused now, and
  the research suite is the evidence for that.
- The CAND-014 extraction boundary is unchanged.

## What This Release Does Not Establish

- It does not establish live-trading readiness.
- It does not enable live trading, live submit, provider execution, broker
  execution, credential loading, or network access.
- It does not weaken any gate, default, or refusal.
- **It does not establish that the audit was complete.** Eight defects were found
  and corrected. That is evidence about what was looked for, not evidence that
  nothing else is there. Five open items are recorded in
  [safety-invariant-audit-followups](../development/safety-invariant-audit-followups.md)
  as decisions rather than corrections.
- The corrections were made by the same agent system that found them. An
  independent review is recommended before any of this is relied on for funded
  use, and no external review evidence is claimed or invented.

## Safety Defaults

- Live trading is disabled by default.
- Live submit is disabled by default.
- Provider execution is disabled by default.
- Broker execution is disabled by default.
- `RiskManager`, approval gates, the kill switch, the dead-man heartbeat and
  audit hash-chain controls remain required, and are stricter than in `v0.6.26`.
- `atlas run --mode live` remains fail-closed (exits 2).
- Per-order human approval is retained everywhere it applied before.
- L3 bounded live autonomy is designed in
  [docs/l3-bounded-live-autonomy-design.md](../l3-bounded-live-autonomy-design.md)
  and **not enabled**. Its fourth requirement — active operator oversight — has
  no definition, and a deadman proves the agent is alive rather than that a human
  is watching.
- L4 remains out of reach without external legal, security, operational, risk,
  broker-adapter and regulatory review by qualified parties, which
  [Bounded Live Autonomy Governance](../bounded-live-autonomy-governance.md)
  requires to be done by them and not by self-assessment.
- This release makes no live-readiness, autonomous-live-readiness,
  profitability, absolute-safety, or future-performance claim.
- This software is not financial advice.

## Known Limitations

- The project remains paper-first and safety-gated.
- External security review is recommended before funded use.
- Live operation requires separate explicit configuration and approvals.
- The clean-room independence caveat carried from CAND-015 applies with more
  force here: the defects, the corrections and the tests pinning them all come
  from the same agent system.
- A full `pytest` run or full `bash scripts/release_check.sh` may exceed local
  interactive timeouts. The `--quick` gate and all targeted checks pass.
- `scripts/local_quick_check.sh` does not run the documentation checkers, so a
  doc edit that trips them passes the quick gate and fails later.
