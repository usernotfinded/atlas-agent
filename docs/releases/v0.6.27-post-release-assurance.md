## Scope Caveat on the Tagged Commit

The tag was cut at `89662d65`, the tip of `main` at publication time, rather than
at the last pure `v0.6.27` cutover commit (`b7e1e55b`). The tagged tree therefore
contains `v0.6.28` candidate work that the `v0.6.27` release notes do not
describe — CAND-034, the research error-code mapping, and the
`validate_provider_id` split. This was a deliberate choice made at publication
time: tagging `b7e1e55b` instead would have excluded the two documents that
record the tag procedure and the partial-tag test trap below. It is recorded here
rather than left implicit.

## Partial-Tag Test Trap (Verified, Not a Regression)

The suite skips tag-dependent tests through a `require_release_tags` fixture when
a checkout carries *no* git tags. Creating `v0.6.27` in an otherwise untagged
clone leaves it *partially* tagged: the fixture stops skipping and 18 tests then
fail because the historical tags they need are absent. This publication was
performed in a checkout carrying all 114 tags, so the condition did not arise.
The gap is in the fixture guarding "no tags" rather than "some tags"; it is
recorded, not changed.
