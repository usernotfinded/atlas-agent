> **Status:** current public GitHub release

> **Previous public release:** `v0.6.26`
> **Next planned release:** `v0.6.28`

## Summary

`v0.6.27` is a **safety-correction release**. Where `v0.6.26` was maintenance
tooling, this one carries the outcome of an audit that walked the ten hard
invariants in
[Bounded Live Autonomy Governance](../bounded-live-autonomy-governance.md) and
asked of each whether the code enforces what the documentation promises.

It did not, in eight places. Seven of them share one shape: a consumer reading
one of two sources that describe the same safety state, with nothing saying the
second source existed.

Alongside the corrections, three candidates landed and the research package lost
roughly 4,700 lines of duplication without any change to its 175 CLI envelopes.

This is a **GitHub-only release**. PyPI was not published. Nothing here enables
live trading, live submit, provider execution, credential loading, or network
access, and no default moves toward permissiveness.

## The Safety Corrections

Six defects came from Atlas carrying **two parallel kill-switch subsystems** —
`.atlas/safety/` (`AdvancedKillSwitch`) and `memory/` (`KillSwitchController`) —
holding separate state, with the commands split between them and nothing
recording the split.

| # | Defect | Consequence | Severity |
|---|---|---|---|
| 1 | The kill switch would not arm when the broker could not be built | An operator trying to stop trading got a refusal, in all three modes | Refused to refuse |
| 2 | `atlas kill` left `can_submit` true | **The live submit path stayed open after an emergency stop** | **Fail-open** |
| 3 | The agent loop ignored the `memory/` switch | `atlas kill-switch enable --mode flatten` did not stop the loop | Refused to refuse |
| 4 | Live-submit opt-in was granted while `atlas kill` was armed | Authority granted during an emergency stop | Refused to refuse |
| 5 | `_display_live_status` misreported readiness | The operator was shown the wrong state | Reporting |
| 6 | `atlas risk status` printed "Kill Switch: Inactive" while armed at flatten | The operator was shown the wrong state | Reporting |

Only **#2** left a live path open. The others failed to refuse while a downstream
gate still held — which is a defence-in-depth loss, not an open door, and is
recorded that way rather than inflated.

A seventh defect of the same shape was found in the research package: the
anti-fabrication scan that stops an artifact claiming capabilities the system
does not have had **two disjoint vocabularies**. Nine modules each carried their
own phrase list; between them the lists held 85 phrases and **the intersection was
empty**. Provider artifacts — written on every research session — did not refuse
the trading-readiness claims that the release-candidate artifacts refused, and
vice versa.

An eighth, in the configuration layer: three separate paths could write a value
the schema could not load back, including a wizard writing a release channel into
a check-frequency field.

Both directions of every one of these were demonstrated by running the code, each
against a control that proves the probe was not vacuous, rather than by reading
it.

## Included Candidates

- **CAND-033: Wire the declared risk limits that no rule reads** — hard invariant
  5 states `RiskManager` enforces limits on position size, notional, daily loss,
  exposure, symbols and leverage. Four had rules; two did not, and a third that
  `atlas risk check` prints to the operator did not exist as a field at all. A
  portfolio 50% down against a 2% declared limit evaluated `allowed=True` with
  zero violations. All three are now enforced. Risk-reducing orders still pass
  every session halt, so a loss limit cannot trap a position open.
- **CAND-035: Absorb the repeated research handler preamble** — 170 handlers
  repeated the same workspace resolution, `no_workspace` branch and two-clause
  exception handling. `cli_commands/research/_envelope.py` now holds it once:
  11,196 lines to 6,578. Verified by driving all 175 subcommands and diffing
  their JSON envelopes against a pre-migration baseline — 0 differences.
- **CAND-037: Absorb the per-artifact helper copies** (partial) — 76 of the 83
  byte-identical copies are gone. Each family was compared on substance before
  being collapsed, including transitive dependencies. `validate_provider_id` was
  found to carry three *disjoint* admission rules under one name and is
  deliberately **not** unified; it remains proposed as a rename.

## Also In This Release

- Every gate failure on the submit path is now recorded in the audit log.
- `guard_sync` admitted `paper` as a live sync broker; the broker allowlist
  existed as three drifted copies and is now one inventory.
- Strategy plugin discovery is cached per process; thirty engine constructions
  went from 104.3 ms to 5.1 ms.
- The dev gate distributes its slowest steps across cores: 356 s to 165 s.
- Structural tests for boundaries the documentation asserted but nothing
  enforced — which modules may reach a broker, which may resolve one for live,
  and that provider output cannot reach execution.

## Safety Boundaries

- This release does not enable live trading or live submit.
- This release does not enable provider execution.
- No autonomous trading is claimed or enabled by this release.
- This release does not place, cancel, or flatten orders on its own.
- This release does not create pending orders or mutate approval queues.
- This release does not call brokers, providers, or network endpoints.
- This release does not load credentials, secrets, or API keys.
- `atlas run --mode live` remains fail-closed (exits 2).
- The risk gate is **tightened** by CAND-033, never loosened: it can only reject
  orders that were accepted before.
- Per-order human approval is retained everywhere it applied before.
- L3 bounded live autonomy remains **designed but not enabled**; L4 remains out
  of reach without external legal, security, operational, risk, broker-adapter
  and regulatory review by qualified parties, which the governance document
  requires to be done by them and not by self-assessment.
- No live-readiness, autonomous-live-readiness, trading safety, broker
  endorsement, or permission to submit orders is claimed.
- No profitability, absolute-safety, or future-performance claim is made.

## Known Open Items

Recorded rather than fixed, each in
[safety-invariant-audit-followups](../development/safety-invariant-audit-followups.md)
with what deciding either way would involve:

- The emergency flatten cannot be reached by escalating — reserved for external
  broker-adapter review.
- The heartbeat commands feed a `DeadmanSwitch` that nothing constructs. Wiring
  it is a decision about who may assert liveness.
- `provider-safety-dossier-summary` documents an argument it cannot accept.
- CAND-034's error-code vocabulary: 136 raised codes reach the operator as a
  generic message. Ratcheted so the backlog cannot grow.
- An absent heartbeat reads as fresh, so the deadman is inert on any path that
  evaluates without recording.

## Known Non-Blocking Warnings

1. A full `pytest` run or full `bash scripts/release_check.sh` may exceed local
   interactive timeouts. The `--quick` gate and all targeted checks pass.
2. Historical candidate-chain docs for pre-`v0.6.27` releases still emit expected
   warnings from `check_candidate_chain.py` because they reflect historical
   planning state rather than current metadata.
3. `scripts/local_quick_check.sh` does not run the three documentation checkers.
   A doc edit that trips them passes the quick gate and fails later in the full
   suite; run them directly after editing docs.
