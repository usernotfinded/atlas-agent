### CAND-034 — the vocabulary question, answered from the existing code

This candidate was held back because adding 136 error messages without deciding
the vocabulary first would make the surface harder to consume, not easier. That
premise was right and the estimate behind it was wrong: **136 codes do not need
136 messages.**

The 148 codes already mapped use **32 distinct messages**, and 62 of them carry a
status different from the code itself — the existing design deliberately collapses
many codes onto few operator-facing sentences, and describes the *artifact*, not
the internal field name. `provider_call_plan_source_missing` reads "Invalid
provider call-plan artifact.", not "source is missing".

Three artifact families that were mapped independently use the **identical**
five-slot pattern:

| Slot | Message | Where it comes from |
|---|---|---|
| identifier | `Invalid research identifier.` | shared, 22 codes use it today |
| malformed | `Research artifact is malformed.` | shared, 13 codes |
| schema | `Unsupported research artifact schema.` | shared, 9 codes |
| not found | `Research artifact not found.` | shared, 13 codes |
| the artifact itself | `Invalid provider <artifact> artifact.` | one sentence per family |

`preflight_freeze`, `opt_in_policy` and `call_plan` each map 10–14 codes onto
exactly these five, with the family sentence carrying 6–8 of them. Nobody
coordinated that; it is what three separate authors each arrived at.

Applying the same pattern to the 136 unmapped codes:

| | codes |
|---|---|
| reuse one of the four shared messages | 21 |
| take their family's sentence | 115, across 13 families |
| **new sentences to write** | **13** |

So the work is thirteen sentences of the form "Invalid provider `<artifact>`
artifact.", plus a mechanical classification of each code into one of five slots
by its suffix. The thirteen families with no mapped code at all are
`trust_decision_blocker` (22 codes), `review_sandbox` (16),
`import_candidate` (15), `mock_response_simulation` (13),
`adapter_interface_contract` (12), `execution_unlock_state` (11),
`response_review_result` (10), `response_schema_contract` (9),
`safety_dossier` (8), `outbound_payload_preview` (7), `final_safety_seal` (6),
`credential_boundary` (4) and `release_candidate_readiness` (1).

**What must not change.** `safe_research_session_error` stays an exact dict
lookup. A derivation rule that built a message from the code at runtime would be
the wrong shape however tidy: 33 raise sites build their code at runtime — for
instance `artifact_store.py` raises `f"ambiguous_{kind.name}_id"` — and a rule
matching a pattern would echo whatever string arrived. The entries are authored
against literals in the source; the fail-safe generic fallback stays for
everything else.

**Blast radius**, measured rather than guessed: 18 assertions on `research_error`
across 5 test files, 4 of which touch the affected families. Those assertions
encode the current contract and each has to be looked at, not bulk-edited.

This is now an implementation task rather than a decision. It stays proposed only
because widening 136 machine-readable statuses is a contract change that should
land as its own reviewed unit.

### CAND-038 — Three admission rules share the name `validate_provider_id`

`CAND-037` collapsed six helper families in `research/` and stopped at the
seventh. `validate_provider_id` has 21 copies that look like duplicates and are
not. Normalising the error code away leaves three **disjoint** admission rules
under one name:

| Rule | Copies | Admits |
|---|---|---|
| `value in _get_disabled_provider_ids()` | 15 | the four disabled external provider ids, **not** `mock` |
| `value == "mock"` | 5 | `mock` only, **not** the external ids |
| either of the above | 1 | all five |

`mock` is not among the disabled ids, so the first two rules accept strictly
different sets rather than one being a subset of the other.

The union belongs to `provider_mock_response_simulation`, and it is not drift.
That module calls the function on two different fields — its upstream preview's
provider id, which is external, and its own artifact's, which must be `mock` —
and re-checks `provider_id != "mock"` immediately after validating its own. One
member of a family being more permissive than its four siblings is the drift
signature, so this was checked by reading both call sites rather than assumed.

What makes it worth doing is the shape of that defence. A permissive validator
followed by a separate strict check is exactly what breaks when someone deletes
the redundant-looking line. Naming the two policies apart removes the need for
the defence instead of relying on it.

**Landed.** `sandbox_contracts` gained `validate_contract_external_provider_id`
and `validate_contract_mock_provider_id`; the 20 single-rule modules keep a
two-line wrapper under a name that says which rule it is, and every call site was
renamed with it. `provider_mock_response_simulation` names
`validate_source_provider_id` for the upstream preview and
`validate_mock_provider_id` for its own artifact, so the `!= "mock"` re-check that
defended the union is no longer load-bearing and is gone.

No admitted set changed. That is asserted per module across the whole provider
universe in `tests/research/test_provider_id_rules_stay_disjoint.py`, not argued —
21 modules x 7 values, zero differences against the pre-rename rules.

Two things the work found that the candidate did not predict:

- A **twenty-second** definition lives in `providers/provider_preflight.py`, and
  it is not a copy: a bounded-string check raising `PreflightValidationError`, in
  a different package for a different purpose. The name therefore carries four
  meanings across the tree, not three. It is out of scope and left alone, which is
  why the new test asserts on the research modules by name rather than on every
  `validate_provider_id` in the source.
- The CLI handler `handle_provider_plan` imported the old name from
  `provider_call_plan`. The rename was scoped to `research/` and missed it, and
  167 research tests failed until it was fixed. The scope of a rename is every
  importer, not every definition.

This is validator naming only: no gate added or removed, and no change to the
risk gate, kill switch, approval queues, broker adapters, or the audit
hash-chain.

## Safety boundaries

No `v0.6.28` planning content enables live trading, live submit, broker or
provider execution, credential loading, network access, order placement,
pending-order creation, or approval queue mutation. `atlas run --mode live`
remains fail-closed. No candidate here moves a default toward permissiveness.

L4 unattended live autonomy remains out of reach without external legal,
security, operational, risk, broker-adapter and regulatory review by qualified
parties, which
[Bounded Live Autonomy Governance](../bounded-live-autonomy-governance.md)
requires to be done by them and not by self-assessment.
