forward to `v0.6.28`.

## Decisions

| id | title | status | accepted |
|---|---|---|---|
| CAND-032 | Deferred domain loading for CLI startup | proposed | no |
| CAND-033 | Wire the declared risk limits that no rule reads | released | yes |
| CAND-034 | Map the research error codes the CLI flattens | proposed | no |
| CAND-035 | Absorb the repeated research handler preamble | released | yes |
| CAND-036 | L3 bounded live autonomy: explicit opt-in and its path | proposed | high risk, not accepted |
| CAND-037 | Absorb the per-artifact helper copies verified identical | released | yes |

The three that did not pass are not blocked on effort:

- **CAND-032** was measured and effectively declines itself. The lazy-import
  lever buys at most 13% of one CLI invocation and at most 4.5% of the suite,
  against threading local imports through a 5.9k-line dispatch whose command
  surface is a pinned trust contract.
- **CAND-034** is a vocabulary decision. Eleven different not-found spellings
  already exist across the `-show` commands; adding 136 more strings without
  deciding the vocabulary first would make the surface harder to consume.
- **CAND-036** is blocked on an undefined requirement, not on implementation.
  The ladder's fourth L3 condition is "active operator oversight", which is
  defined nowhere — and a deadman proves the agent is alive, not that a human is
  watching.

Accepting CAND-033 authorized a runtime change, which this gate's earlier text
did not anticipate. It tightens the deterministic risk gate and can only reject
orders that were previously accepted; it enables nothing.

## Selection rules

Any future `v0.6.27` candidate must satisfy the repository's candidate selection
rules before acceptance:

1. No live trading enablement — fail-closed defaults unchanged.
2. No broker/provider execution enablement — no direct AI-to-broker path.
3. No secrets or credentials committed.
4. No unsafe marketing claims — no promises of specific returns, eliminated
   risk, live readiness, or autonomous trading readiness.
5. Protected runtime boundaries preserved — `RiskManager`, approval queues, kill
   switch, heartbeat, deadman, audit hash-chain, live-submit opt-in, and
   `can_submit` are not bypassed.
6. Small, reviewable candidate batches that are independently valuable.
7. Deterministic test and documentation coverage.
8. Green verification before acceptance.
9. The CAND-014 provider-artifact extraction boundary is not broadened beyond
   `src/atlas_agent/research/provider_mock_response_final_safety_seal.py`.
